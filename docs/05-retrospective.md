# 复盘

关键困难是区分“找到了相关主题”和“原文能回答用户的具体问题”。例如账号开通时间不等于开通费用，年假提前申请时间不等于年假天数；一个受支持子问题不能掩盖另一个未知子问题。审阅发现这些反例后，项目改为有限问句词表、逐子句检查、无法识别时保守返回缺口。

另一难点是区分模型动作和可追溯证据。检索只显示候选，必须调用读取工具；最终答复从读取的原文构造，而模型只提交结构化决策。两份同主题标注值冲突时一起展示，不按日期擅自选定。

限制是合成数据和人工标注规模很小，别名、属性和词表不保证通用理解，模型与工具都可能失败。下一步应在获得真实文档授权后，建立标注集，评估中文改写召回、细粒度蕴含、矛盾与版本有效范围，并加入人工复核和权限控制。实际运行范围见 [评估](03-evaluation.md)。

复审中发现，单纯检查标注值出现在原文并不能证明原文肯定该值；将处理耗时与允许开始的日期合并也会造成答非所问。因此收窄为受支持的正向句式，无法验证的资料直接要求人工核实。这样会降低兼容性，但比将不确定的资料标为已支持更可靠。同一属性的不同 key 也需比较；SDK 同一模型消息中的并列调用要与观察工具结果之后的动作区分。
