# 方案设计

`search_documents` 返回候选元信息；`read_excerpt` 根据候选 ID 读取当前资料的原文和版本；模型通过 `submit_decision` 选择 `answer`、`clarify` 或 `stop` 并提交 ID。Claude Agent SDK 0.2.175 使用自定义进程内 MCP 工具、允许列表、空内置工具列表与 `max_turns` 运行模型循环；业务层单独限制工具调用次数。业务代码记录实际结果和 `reason`，不记录模型内部推理。

检索使用合成数据的别名和保守字符相似度，无向量检索、重排或外网搜索。模型先检索原词，可按结果决定改写；最终证据需通过预设同义词表与原问题主题关联，而非只用原问题字面查询，故已读到的同义改写结果不会被忽略。不能确认关联的已读资料单独标为 `unverified_candidates` 并请求确认，不能视为支持答案。当前问题能确定主题时只使用该主题；代词追问可引入最近的用户问题，历史助手内容不是证据。必须实际搜索并读取已识别主题的所有候选文档，才会进入回答或冲突判断。

每个文档由维护者提供 `key`、`value`、`aspects`、`scope` 和 `passage`。受限正向事实语法把每个属性映射到本例中一个主题，解析出的值及适用对象必须与标注一致。无法识别的内容拒绝加载；这刻意限制了可用资料类型，不能自动验证任意自然文档。同一属性的资料即使 key、别名不同也会一起召回并比较；值不同视为冲突，同值但原文不同也需核实，不会把日期当优先级。文档标注的适用对象未在问题或追问上下文中明确时请求确认。

回答由读取到的原文按 ID 和版本拼接，不直接采用模型自由文本。业务层用有限问句词表及逐子句检查问题属性；不认识的属性、动作、条件与未知子句返回缺口，允许展示“不能回答完整问题”的相关原文。该规则是保守覆盖，不具备通用语义理解；人工标注不正确、隐含条件或复杂语句仍可能超出能力，需要扩展语料与人工评估。

`next_action` 只表示工具执行顺序。实际 SDK 消息会记录每个工具请求的 ID 与消息 ID；同一消息包含多个请求时标 `same_model_message`，不同消息且后一请求在前一返回后出现时标 `after_tool_result`。不以同一消息里的并列调用证明模型观察后调整；Mock 则标 `scripted_sequence`。

`--fail-once` 用于注入一次检索或读取错误；恢复必须实际再次调用成功才能解除错误状态。达到工具次数上限、SDK 失败或模型未提交有效决策均不会生成成功回答。
